# QUALITY ANALYST DASHBOARD

The aim of this dashboard is to make my job as an quality analyst easier by providing a visual representation of the data I work with on a daily basis. The dashboard will allow me to quickly identify trends, track performance metrics, and make data-driven decisions.

## The Business and Industry

Company: GMA Global (BPO)
Client: Hiscus
Campaign: Customer Service - Insurance
Brands: Home Insurance

- Bright Insurance
- General Insurance
- Grand Insurance

The business reports on the outcomes of onshore(Client) audits. All data analysis is based on customer and agent interactions. Included in the data, as an operational analysis of offshore(Company) audits. The reporting data is separated where the ultimate reporting is mainly based on onshore audits and outcomes. Offshore audits are used to establish errors within the operations as a first point of action for internal observations, interventions and evaluations. This is to prevent onshore call outs and to strengthen operational success.

The interactions of audits are based on customer and agent interaction in all relevant KPI's. The reporting is from agents to team leaders and operational data analysis of outcomes.  

## The dashboard will include the following features

- **Data Visualization**: Graphs and charts to represent key performance indicators (KPIs) and trends over time.
- **Interactive Filters**: Ability to filter data by date range, product, or other relevant criteria to focus on specific areas of interest.
- **Real-time Updates**: The dashboard will be updated in real-time to reflect the most current data available, ensuring that I always have access to the latest information.
- **Customizable Layout**: The ability to customize the layout of the dashboard to suit my specific needs and preferences, allowing me to prioritize the information that is most important to me.
- **Alerts and Notifications**: Set up alerts and notifications for specific KPIs or thresholds, so I can be immediately informed of any significant changes or issues that require attention.
- **Export and Share**: The ability to export data and visualizations in various formats (e.g., PDF, Excel) and share them with colleagues or stakeholders for collaboration and reporting purposes.
- **User-friendly Interface**: A clean and intuitive interface that is easy to navigate, ensuring that I can quickly access the information I need without unnecessary complexity.
- **Integration with Existing Tools**: The dashboard will integrate with existing tools and systems used in my workflow, allowing for seamless data import and export, as well as compatibility with other software applications.
- **Data Security and Privacy**: Implementing robust security measures to protect sensitive data and ensure compliance with relevant data privacy regulations.
- **Performance Monitoring**: The ability to monitor the performance of various processes and systems, identifying areas for improvement and optimization.

## Dashboard Implementation

The dashboard will be built using the following technologies:

- **Frontend**: Basic HTML and CSS
- **Backend**: JavaScript
- **Data Source**: Excel and CSV files
- **Data Set**: JSON files
- **Interpreter**: PowerShell Scripts

## Dashboard Foundation

The dashboard will be built using a combination of HTML, CSS, and JavaScript. The HTML will provide the structure and layout of the dashboard, while the CSS will be used to style the visual elements and create an appealing user interface. JavaScript will be used to handle data processing, interactivity, and real-time updates.

### Frontend

The frontend of the dashboard will be designed to be user-friendly and intuitive, allowing me to easily navigate through the various features and access the information I need. The layout will be customizable, enabling me to prioritize the most important KPIs and metrics.

- HTML will be used to create the structure of the dashboard, including sections for data visualization, filters, alerts, and notifications.
- CSS will be used to style the dashboard, ensuring that it is visually appealing and easy to read. This will include the use of colors, fonts, and spacing to create a clean and organized layout.

### Backend

The backend of the dashboard will be responsible for processing the data and providing the necessary functionality to support the frontend features. JavaScript will be used to handle data manipulation, filtering, and real-time updates.

- JavaScript will be used to fetch data from the JSON files generated by the PowerShell scripts, process the data, and update the visualizations on the dashboard in real-time.

### Data Source

The data source will be collected from PowerBI and stored in a file directory as an Excel or CSV file, where the scripting can collect and interpret the data and push to a JSON file that will be translated by the Javascript file to be displayed on the dashboard. The data will be updated in real-time to ensure that the dashboard always reflects the most current information available.

- Excel and CSV files will be used to store the data collected from PowerBI, allowing for easy access and manipulation by the PowerShell scripts.

### Data Set

The data set will contain the information that will be displayed on the dashboard. It will be structured in a way that allows for easy access and manipulation by the JavaScript code.

- The data set will be generated from the Excel and CSV files, containing the necessary information for the dashboard visualizations.
- The data set will be structured to allow for easy filtering and querying of data, enabling me to quickly access the information I need.

### Interpreter

The interpreter will be responsible for converting the data collected from Excel and CSV files into a format that can be easily interpreted by the dashboard. This will involve processing the data and generating JSON files that can be used by the JavaScript code to update the visualizations on the dashboard.

- PowerShell scripts will be used to collect and interpret the data from the Excel and CSV files, generating JSON files that can be used by the JavaScript code to update the visualizations on the dashboard.

## Codework Systems

## PowerShell Script

- The script has to be able to take multiple data files (excel/csv) and convert them into a single JSON file that can be used by the dashboard.
- This JSON file will generate to support the data.js file to assist in updating the dashboard.
- The focus is to create a script that can be used to collect and interpret the data from the Excel and CSV files, generating JSON files that can be used by the JavaScript code to update the visualizations on the dashboard.
- With multiple data files, the script should be able to handle different data structures and formats, ensuring that the resulting JSON file is consistent and usable by the dashboard.

## Javascript

- The data.js file will support the dashboard.js file to update the dashboard with the latest data from the JSON file generated by the PowerShell script.
- The dashboard.js file will be responsible for handling the data processing, filtering, and real-time updates of the dashboard visualizations.
